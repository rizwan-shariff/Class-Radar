# ClassRadar — Complete Frontend Development Handoff Specification

**Product:** ClassRadar (*"Your Campus. In Sync."*)  
**Design System Identity:** Academic Utility Modern  
**Version:** 2.0.0 (Production Handoff Spec)  
**Font Stack:** Inter (Google Fonts), Tabular Figures / Monospace for IDs & Telemetry  
**Color Tokens Reference:** Indigo Primary (`#4F46E5`), Emerald Safe/Present (`#10B981`), Amber Substituted/Warning (`#F59E0B`), Rose Critical/Debarred (`#EF4444`), Surface Neutral (`#FAFAFC` / `#FFFFFF`), Dark Navy Display Canvas (`#0A0F1D`).

## 1. Authentication & Portal Gateway

### Screen 1: Institutional Portal Login & Role Authentication
* **Screen Name:** Institutional Portal Login & Role Authentication (`{{DATA:SCREEN:SCREEN_7}}`)
* **Role:** Unauthenticated Guest / All Institutional Personas (Student, Faculty, Administrator)
* **Purpose:** Single sign-on and institutional credentials verification with dual-factor role selection, multi-campus mesh server connectivity display, and security compliance badges.
* **Navigation Entry Point:** Direct URL route `/login` or default redirect when unauthenticated session token is absent.
* **Component Hierarchy:**
  * `PortalLayout` (Two-column split on desktop)
    * `LeftBrandHeroPanel`
      * `BrandHeader` (ClassRadar official SVG logo + "Your Campus. In Sync.")
      * `InstitutionalEndorsementCard` (Dean's official quote, accreditation badges: NAAC A++, UGC Autonomy)
      * `ActiveTelemetryStatus` (Mesh network status, 3 Engineering blocks online)
    * `RightAuthFormContainer`
      * `RoleSelectorTabs` (Segmented control: Student, Faculty, Admin)
      * `LoginForm`
        * `InstitutionalIDInput` (USN for students, Faculty ID for professors, Staff ID for admins)
        * `PasswordInput` with Show/Hide toggle
        * `CampusDomainSelect` (Main Campus, City Annex, Computing Center)
        * `RememberMeCheckbox` & `ForgotPasswordLink`
        * `SubmitCTAButton` ("Sign In to ClassRadar")
      * `SSOAlternativeGroup` (Google Workspace for Education, Microsoft 365 Campus OAuth)
      * `SecurityFooter` (256-bit TLS, FERPA/UGC Data Compliance)
* **Buttons & Expected Actions:**
  * `Role Tabs (Student / Faculty / Admin)`: Switches active authentication role scheme, dynamic input placeholder, and validation rules in local state.
  * `Sign In to ClassRadar (Primary)`: Submits credentials to `/api/v1/auth/login`. On 200 OK, stores JWT/session cookie and redirects to respective role portal.
  * `SSO Buttons (Google / Microsoft)`: Redirects window to OAuth provider redirect URL `/api/v1/auth/oauth/{provider}`.
  * `Forgot Credentials`: Triggers password recovery drawer/modal or institutional IT ticket handoff.
* **Forms & Input Fields:**
  * `Institutional Identifier`: Text field with client-side pattern validation (e.g., student USN regex `^[1-4][A-Z]{2}[0-9]{2}[A-Z]{2}[0-9]{3}$`).
  * `Password`: Password masked input, min 8 characters.
  * `Campus Node`: Native select dropdown for institutional branch node.
* **Required UI States:**
  * *Default / Rest*: Clean input wells, student tab selected by default.
  * *Active / Focus*: Indigo focus ring (`ring-2 ring-indigo-500/20 border-indigo-600`).
  * *Loading / Submitting*: Disabled submit button with spinner, input fields read-only.
  * *Authentication Error*: Rose border on credential inputs with banner: `"Invalid Institutional Credentials or Unassigned Role"`.
  * *Network Disconnect*: Amber alert when campus server gateway times out.
* **Responsive Behaviour:**
  * Desktop (1366px–1920px): 50/50 split canvas with left brand storytelling and right auth container.
  * Tablet (768px): Stacks brand hero banner above the authentication card.
  * Mobile (375px–430px): Hides promotional quote hero, displays full-width mobile card with touch-friendly 44px input targets.
* **Relevant Reusable Components:** `Button` (Primary, Secondary, Ghost), `Input`, `Select`, `Badge`.
* **Backend Integration Requirements:**
  * `POST /api/v1/auth/login` (Body: `{ identifier, password, role, campus_id }`)
  * `GET /api/v1/auth/sso/providers`
  * `GET /api/v1/telemetry/mesh-health` (Campus ping & live status)

* **Purpose:** Daily and weekly academic scheduling, quick-glance class alerts, UGC 75% attendance threshold monitoring, and what-if bunk sandbox.
* **Navigation Entry Point:** Authenticated default route `/student/dashboard` or `/student/timetable`.
* **Component Hierarchy:**

  * `SideNavBar` (Dashboard, Schedule, Attendance, Free Rooms, Profile)

      * `PeriodSlotCards` (P1 to P8 with room code, instructor, status badge, live progress ring)

      * `UGCAttendanceRingWidget` (81.8% radial progress, 75% critical cutoff line)
      * `WhatIfBunkSandboxCard` (Interactive range sliders: Skip vs. Attend with real-time recalculation)
      * `VacantRoomNearbyList` (Free study spaces)
* **Buttons & Expected Actions:**
  * `Day Selector Tabs`: Filters active period slot list to chosen weekday without page reload.
  * `Launch QR Scanner CTA`: Navigates to `/student/scan-qr` or opens scanner modal.
  * `Simulate Sliders`: Local client-side mathematical recalculation of projected attendance.
  * `Dispute Attendance`: Triggers attendance discrepancy grievance form modal.
* **Forms & Input Fields:**
  * `Classes to Skip Slider`: Range input (0 to 10).
  * `Classes to Attend Slider`: Range input (0 to 10).
* **Required UI States:**
  * *Live Class*: Indigo border with glowing pulse beacon.
  * *Substituted Class*: Amber left-border with replacement faculty name pill.
  * *Cancelled Class*: Rose background tint, struck-out text, cancellation reason.
  * *Attendance Deficit Warning*: Rose indicator if overall percentage < 75%.
* **Responsive Behaviour:**
  * Desktop: 3-column layout (Sidebar + Grid + Sandbox Rail).
  * Tablet: Sandbox rail reflows below timetable schedule.
  * Mobile: Covered natively by dedicated PWA screen.
* **Relevant Reusable Components:** `TopNavBar`, `SideNavBar`, `Badge`, `card-slot`, `widget-kpi`, `Modal`.
* **Backend Integration Requirements:**

### Screen 5: Faculty Live QR Attendance Engine & Roster Control
* **Screen Name:** Faculty Live QR Attendance Engine & Roster Control (`{{DATA:SCREEN:SCREEN_10}}`)
* **Role:** Faculty
* **Purpose:** Live classroom dynamic TOTP QR code broadcaster, real-time presence telemetry counter, late scan controls, and live student attendance overrides.
* **Navigation Entry Point:** Direct action from Faculty Hub `/faculty/session/{session_id}/live`.
* **Component Hierarchy:**
  * `LiveHeader` (Course: CS302, Room 301, Period 3, Live Timer)
  * `TwoColumnEngineLayout`
    * `LeftDynamicQRPane`
      * `RotatingQRCodeContainer` (SVG QR code, auto-refreshes every 15s)
      * `TOTPTimerCountdown` (Progress ring with "15s Security Cycle")
      * `SessionPasscodeFallback` (6-digit fallback PIN: `#301-842`)
      * `SecurityProtocolPill` (Rotating cryptographic nonce, geofence active)
      * `SessionControls` (Pause QR, Extend Duration, Lock Roster, End Class)
    * `RightLiveRosterPane`
      * `LiveHeadcountBar` (e.g. 56 Present / 8 Absent / 87.5% attendance)
      * `LiveStudentRosterTable`
        * Columns: USN, Student Name, Check-in Time, Device Status, Action Overrides
        * Override buttons: `Verify Present`, `Excuse Late`, `Revoke Scan`
* **Buttons & Expected Actions:**
  * `Pause / Resume QR`: Pauses rotation and invalidates active token on backend.
  * `Lock Session`: Closes check-in permanently; sets remaining unmarked students to absent.
  * `Verify Present (Row Action)`: Manually sets student status to present (`POST /api/v1/attendance/manual-override`).
  * `Excuse Late (Row Action)`: Marks student present with late flag.
  * `Revoke (Row Action)`: Revokes verified status if student is caught proxying.
* **Forms & Input Fields:**
  * `Student Search Filter`: Instant text filter by USN or student name.
* **Required UI States:**
  * *QR Active*: Rotating indicator, countdown active.
  * *QR Expiring*: Amber warning indicator during the last 3 seconds of a cycle.
  * *Roster Locked*: Greyed-out QR pane, read-only audit status.
* **Responsive Behaviour:**
  * Desktop (Primary target for podium laptops): Split 50/50 view.
  * Tablet: QR engine stacks above live roster table.
* **Relevant Reusable Components:** `Button`, `Table`, `Badge`, `Input`.
* **Backend Integration Requirements:**
  * `WebSocket /ws/v1/attendance/live/{session_id}` (Pushes real-time scans as students check in)
  * `GET /api/v1/attendance/qr-token?session_id={id}` (Fetches next signed 15s TOTP token)
  * `POST /api/v1/attendance/session/lock`
  * `POST /api/v1/attendance/override` (Body: `{ student_usn, status, session_id }`)

## 8. Shared Components & Design System Architecture

### 8.1 Core Component Inventory
1. **`TopNavBar`**: Full-width fixed 56px header with logo, term badge, WebSocket latency indicator, notification bell, and synchronized role switcher dropdown.
2. **`SideNavBar`**: 256px docked navigation rail with active route indicator, icon set, and role-specific action CTAs. Automatically collapses to a 64px icon rail on tablets (<1024px).
3. **`BottomNavBar`**: 64px mobile PWA navigation with 5 slots and centered elevated **Scan QR** FAB.
4. **`Button`**: Standard variants (`primary`, `secondary`, `ghost`, `danger`, `success`) across 3 sizes (`sm` 32px, `md` 36px, `lg` 44px) with accessible focus rings and touch padding.
5. **`Input` & `Select`**: High-contrast form controls with floating labels, error icons, and clear focus states.
6. **`Badge`**: Semantic status tags (`PRESENT`, `LIVE CLASS`, `SUBSTITUTED`, `CANCELLED`, `DEFICIT`, `SAFE BUFFER`).
7. **`Table`**: Data grid container with 48px row density, tabular numeric fonts for USNs and percentages, row hover styling, and pagination.
